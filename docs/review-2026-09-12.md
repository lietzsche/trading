# 운영 코드 점검 및 개선

## 점검 범위

FastAPI 인증·관리 API, 데이터 수집·자동매매 스케줄러, Pandas 계산,
React 사용자·관리자 화면과 PWA, Docker Compose·배포 스크립트,
기존 DB 마이그레이션 및 테스트를 검토했다. 실제 계좌 주문을 시험 실행하거나
사용자의 계산 설정·자동매매 설정을 임의로 변경하지 않았다.

점검 당시 계산 설정은 주식 상승 10%/하한 -5%, Upbit 상승 20%/하한 -10%,
둘 다 분석 60일이었다. 최근 24시간 DB 오류 집계는 주식 이력 ConnectError 7건,
Upbit 이력 HTTPStatusError 1건, 배당 수집 HTTPStatusError 1건이었다.
이 집계만으로 모든 오류가 일시적이라고 단정하지 않는다.

## 이번에 개선한 내용

| 영역 | 확인한 문제와 개선 |
| --- | --- |
| 계산 설정 | 상승률 0%의 무한 반복, NaN/Infinity·음수 가격 등을 차단. 상승률 1% 이상, 하한 -99% 이상 및 상승률보다 작게, 분석 3~200일로 화면·API 검증을 일치시킴. |
| 계산 안전성 | 반복 횟수/숫자 범위 초과 시 422로 중단. 0원 시세로 추천을 생성·삭제하지 않고 기존 추천 보존. 정상 레벨 갱신식은 유지. |
| 자동매매 | 같은 프로세스의 수동/스케줄 실행 중복 방지. 활성 사용자만 처리하고 주문 직전 설정·키를 재확인. 계정별 오류 격리, 가용 수량 0인 매도 제외. |
| 추천 갱신 | 특정 종목의 가격 조회 실패가 다른 종목의 갱신까지 막지 않도록 실패 종목은 유지하고 개별 오류를 기록. |
| 권한·사용자 | 비활성화 시 자동매매도 같은 SQL 트랜잭션에서 해제. MASTER 본인 비활성화/강등 방지, 관리자 권한 회귀 테스트. |
| 외부 계좌 오류 | 일시적 연결 실패/429로 자동매매를 해제하지 않음. 계좌 인증 오류만 해당 키 해제. 조회 실패를 미보유로 오인하지 않도록 구분. |
| 계좌 평가 | KRW 시세가 없는 자산은 0원/-100% 대신 확인 불가. 확인된 평가금 소계와 제외 자산 안내. 다른 통화 기준 평균 매수가로 KRW 수익률을 잘못 계산하지 않음. |
| 화면 | 탭 이동·오류 필터 조회의 오래된 응답 무시, 조회 실패 후 재시도, 일반 사용자 초기 화면, 입력 오류 메시지 및 중복 클릭 처리 개선. |
| 주문·프로필 | 일부 체결 후 취소를 전체 체결 완료로 표시하지 않음. 프로필 저장 시 입력하지 않은 전화번호 보존. 신규/변경 비밀번호의 BCrypt 72바이트 제한 검증. |
| 운영 상태 | 의존 서비스 장애 시 health HTTP 503. 수동 작업의 실패/일부 실패/중복 실행을 성공으로 보고하지 않음. DB 연결 대기 3초 제한. |
| 배포·캐시 | DB 마이그레이션 성공 후 API 시작, 모든 서비스 health 확인 후 배포 완료. API 응답 no-store, 없는 API는 HTML 대신 JSON 404. |
| 정리 스크립트 | `down.sh`의 지역변수 초기화 순서 오류 수정. 실제 Docker 대신 모의 명령과 임시 폴더를 사용한 정리 회귀 테스트 추가. |
| 회귀 방지 | API·계산·프런트엔드 테스트 확대 및 push/PR 자동 테스트 CI 추가. |

기존 추천 정렬인 **갱신 단계 내림차순 → 목표 도달률 내림차순**은 유지한다.
계산 안전장치를 제외한 매수·매도 전략이나 투자 비중은 임의로 변경하지 않았다.

## 다음 개발 우선순위

1. **주문 결과 재조정과 영속적 중복 방지**: 거래소가 주문을 받았지만 응답이 끊기거나
   DB 저장이 실패하는 경우를 주문 식별자로 조회·복구하는 구조가 필요하다.
   이번 실행 잠금은 단일 프로세스용이며 여러 API 인스턴스나 재시작을 넘는 중복 방지는 아니다.
2. **DB 복구 체계**: 현재 저장소에는 기존 DB를 전제로 하는 증분 SQL만 있다.
   빈 볼륨용 전체 초기 DDL, 버전별 마이그레이션 기록, 암호화 백업·복원 검증을 추가해야 한다.
   `./down.sh`는 의도대로 데이터 볼륨까지 삭제하므로 재시작 용도로 쓰면 안 된다.
3. **주문·시세 처리 확장**: 주문 내역은 최근 200건, 거래소 상태 동기화는 최근 100건이다.
   서버 측 전체 이력 페이징과 미체결 주문 우선 동기화가 필요하다.
   최소 매도 금액 미달 소액 보유분, 수량 0인 자산의 계산 입력 제외도 별도 검증 대상이다.
4. **추천 전략 검증**: 추천 선정식의 원 단위 반올림은 1원 미만 종목에서 비율을 왜곡할 수 있다.
   소수 가격 처리, 거래량 조건, 추천 미달 시 매도 정책은 과거 데이터로 비교한 뒤 바꾸는 편이 안전하다.
5. **운영·보안**: 로그인 시도 제한, 비밀번호 변경 시 기존 세션 폐기, API 키 암호화 저장,
   재부팅 후 자동 복구 정책, 외부 공급자 전역 호출량/차단시간 제어, 오류 로그 보존기간을 보강할 수 있다.
6. **수집 범위와 화면 검증**: 배당은 현재 네이버 목록 첫 페이지 기준이며 전체 배당주가 아니다.
   전체 페이지 수집·기준일 표시 및 실제 Android 설치/PWA·모바일 브라우저 E2E 테스트가 남아 있다.

외부 수집 실패·호출 제한은 계속 발생할 수 있다. 모든 운영 오류가 사라졌다는 의미가 아니며,
반복되는 오류는 오류 화면의 구분·내용 필터로 확인한다.

## 검증 결과

- API·자동매매 61개, 계산 서비스 48개, 프런트엔드 9개 테스트 통과(총 118개).
- Python 테스트는 네트워크를 차단한 컨테이너에서 실행했다.
- 프런트엔드 production 빌드 및 모의 Docker 기반 `down.sh` 테스트 통과.
- `./reup.sh` 완료: 마이그레이션 성공 종료, API·계산 서비스·PostgreSQL healthy.
- 기존 Quick Tunnel URL·PID 유지, 공개 HTTPS 페이지 및 health HTTP 200 확인.
- 배포 직후 로그 검사에서 새 오류를 발견하지 않았다. 실제 거래 주문 및 Android 단말 E2E 검증은 하지 않았다.

## 배포 동작 근거

Compose의 `service_completed_successfully`로 마이그레이션 완료를 선행 조건으로 하고,
`up --wait --wait-timeout 180`으로 서비스 준비 상태를 확인한다.
[시작 순서 공식 문서](https://docs.docker.com/compose/how-tos/startup-order/),
[compose up 공식 문서](https://docs.docker.com/reference/cli/docker/compose/up/).
