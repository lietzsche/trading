# docfig — 문서 그림 넣기

HTML 문서에 **데이터가 어디로 흐르는지, 무엇이 무엇과 이어지는지, 어느 단계·주체가 어느 표·저장소를 쓰고 읽는지**를 인라인 SVG 그림으로 넣는다. 그림은 문서 안에 직접 쓴 SVG라 외부 라이브러리·이미지·스크립트가 없고, 오프라인·폐쇄망 환경에서도 그대로 열린다. 보조 도구는 `skills/docfig/scripts/figlib.py`(단독 복사본으로 둔 프로젝트에서는 해당 스킬 폴더의 `scripts/figlib.py` 또는 `figlib.py`). 사용자의 언어로 대화한다.

## 입력과 시작하기

- 요청에서 **대상 HTML 문서 경로**(지정하지 않으면 `docs/` 아래 관련 HTML 문서 탐색)와 **그림으로 보여 줄 대상**(흐름, 시스템 구조, 다대다 매핑 등)을 확인한다.
- 코드·설정·기존 문서에서 직접 확인할 수 있는 사실은 먼저 조사하고 사용자에게 다시 묻지 않는다.
- 문서 대상이나 그림 범위가 크게 갈릴 때만 한 번에 한 질문씩 확인한다. 선택형 질문은 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따른다.

## 1. 그릴지 말지

- 그림은 **글로 조립해야 알 수 있는 구조**를 한눈에 보여 줄 때만 넣는다. 한 문장이면 끝나는 내용은 문장으로 둔다.
- **이름이 아니라 동작을 그린다.** 상자만 늘어놓지 말고, 데이터가 지나는 길·넘는 경계·생기거나 사라지는 연결을 그린다.
- **화살표에 뜻을 적는다**(`읽기`, `덮어씀`, `통과하면`, `옮기기 없음`). 뜻 없는 화살표는 "관련 있음"밖에 말하지 않는다.
- **있는 것과 없는 것을 구분한다.** 아직 없는 단계·연결은 빨간 점선(`gap`)으로 그린다. 계획을 지금 있는 것처럼 그리지 않는다.
- 그림이 표를 대신하지 않는다. 기존 표·글은 남기고(검색·복사·스크린리더용) 그림을 그 앞에 둔다.

## 2. 어떤 그림을 쓸지

| 보여 줄 것 | 그림 | `figlib` |
| --- | --- | --- |
| 순서대로 흐르는 처리·데이터 (파이프라인 단계, 배포 순서, 반영 절차) | 흐름도 | `Flow` + `box`·`arrow` |
| 구성요소와 연결 (시스템 연결, 있음·없음) | 구조도 | `Flow` + `box(kind='group')` 묶음 |
| 다대다 관계 (단계 × 표, 주체 × 저장소, 환경 × 설정, 명령 × 대상) | 매핑(격자) | `matrix` |

다대다 관계를 선으로 이으면 엉킨다. 그럴 때는 격자(매핑)로 그린다.

## 3. 모양의 뜻 (모든 문서에서 같게)

| `box` kind | 뜻 | `matrix` 칸 | 뜻 |
| --- | --- | --- | --- |
| `step` | 단계·명령·처리 | `w` | 씀 (덮어씀·병합·다시 만듦·추가는 칸 글자로) |
| `llm` | LLM·모델을 부르는 곳 | `rw` | 읽고 씀 (캐시 등) |
| `item` | 표·파일·구성요소 | `r` | 읽음 |
| `pii` | 개인정보·민감정보 있음 | `c` | 자리만·빈 표 |
| `person` | 사람이 하는 일 | `h` | 사람이 함 |
| `ok` | 완료·통과 | `ok` | 완료·있음 |
| `gap` | 아직 없음·막힘 (빨간 점선) | `f` | 아직 없음 (빨간 점선) |
| `group` / `band` | 묶음 테두리 / 배경 띠 | 행의 `pii=True` | 왼쪽 갈색 막대 |

- 범례(`legend`)는 같은 모양이 그림에 여러 번 나올 때만 넣는다.
- 색은 `figlib`의 그림 전용 변수(`--fg-*`, 밝은·어두운 화면 둘 다)로만 쓴다. 문서마다 다른 CSS 변수에 기대지 않는다. `Doc`이 처음 그림을 넣을 때 그 CSS를 `<style>`에 한 번 넣는다(`/* docfig */` 표시).

## 4. 그리는 규칙

- `viewBox` 폭은 내용에 맞게 정한다(넓은 흐름 1000 안팎). 가로로 흐르면 왼쪽 → 오른쪽, 두 줄이면 아랫줄은 오른쪽 → 왼쪽으로 이어 그린다.
- **격자에 맞춘다.** 상자 높이·간격을 같게, 같은 줄은 같은 y. 화살표 사이 간격은 글자가 들어갈 만큼(30px 이상, 글자가 있으면 `text_width`로 계산).
- 글자는 11~13px, 상자 안은 한두 단어. 설명 문장은 `figcaption`에 쓴다.
- 그림 하나에 주장 하나. `Flow(w, h, label, mid)`의 `label`은 그림이 말하는 한 문장(스크린리더용), `mid`는 문서 안에서 겹치지 않는 짧은 id(화살촉 id에 쓰임).
- `figure(svg, caption, fid)`의 `caption`은 무엇을 보여 주는지·읽는 법, `fid`는 문서 안 고유 id.
- 비밀정보·민감 업무 데이터는 그리지 않는다: 토큰, 비공개 접속 주소, 실제 고객명·개인정보, 외부 노출 금지 이메일. 프로젝트 문서에 환경별 실제 이름 대신 논리 이름을 쓰는 규칙이 있으면 그 규칙을 따른다.

## 5. 실행 순서

1. **사실을 먼저 확인한다.** 그림은 실제 코드·쿼리·설정·스크립트·문서에서 확인한 것만 그린다. 문서 내용이 코드와 다르면 문서 글부터 고친다.
2. 그림 생성 스크립트를 임시 폴더(scratchpad 또는 OS 임시 폴더)에 작성해 실행한다. 일회성 생성 스크립트는 저장소에 커밋하지 않는다.
   ```python
   import sys
   sys.path.insert(0, 'skills/docfig/scripts')  # 프로젝트 내 figlib.py 위치에 맞게 지정
   from figlib import Flow, matrix, figure, Doc

   d = Doc('docs/<문서>.html')
   d.insert_before('<h2 id="s3">', figure(svg, '설명', 'fig-xxx'))   # 또는 insert_after, replace, replace_re
   # 문서가 '버전 x.y' 표기와 '변경 이력' 표·archive/ 보관을 사용하는 경우에만 호출:
   # d.bump('그림 추가: …', date='YYYY-MM-DD')
   d.save()
   ```
   - 판 올림(`d.bump`)은 대상 문서가 판 번호(`버전 x.y`)와 `변경 이력` 표를 관리하는 경우에만 프로젝트 문서 규칙에 맞춰 수행한다(오탈자·위치 미세 조정만이면 올리지 않으며, 한 작업에서 문서당 한 번만 올린다).
   - 기준 문자열(`anchor`)이 문서에 정확히 한 번 있어야 넣는다(아니면 멈추고 확인).
3. 점검한다.
   ```bash
   python skills/docfig/scripts/figlib.py check docs/<문서>.html
   python skills/docfig/scripts/figlib.py shot  docs/<문서>.html <임시폴더>
   ```
   `shot`이 그림마다 밝은·어두운 PNG를 만든다. **PNG를 직접 열어** 글자 겹침·잘림·화살표가 상자를 뚫는 곳이 없는지 보고, 있으면 좌표를 고쳐 다시 넣는다(판 올림을 썼다면 문서를 `git checkout`으로 되돌리고 새로 생긴 보관본 파일도 지운 뒤 다시 실행해야 판·보관본이 꼬이지 않는다).
4. 프로젝트의 `README.md` 문서 목록 설명이나 별도 문서 검증 스크립트가 있으면 함께 갱신·통과시킨다.
5. 프로젝트의 커밋·푸시 규칙(`AGENTS.md` 또는 사용자 요청)이 있으면 변경한 문서(및 생성된 보관본)만 명시적으로 스테이징하여 커밋·푸시한다.
6. 결과 보고: 어느 문서 어느 절에 무슨 그림을 넣었는지, 각 그림이 보여 주는 핵심 내용 한 줄, 점검 결과(접근성·링크 `check` 및 밝은·어두운 화면 `shot` 확인 여부)를 간결하게 답한다.

## 6. 스크린샷과 Windows 계정 잠금 (주의사항)

- **Windows에서 Chrome·Edge를 `--headless`로 직접 띄우지 않는다. 스크린샷은 반드시 `figlib.py shot`으로만 찍는다.**
- 이유: Windows용 Chrome은 새 프로필로 시작할 때마다 "Windows 암호가 비었는지" 확인하려고 빈 암호로 로컬 로그인(`LogonUserW`, 로그온 유형 2)을 한 번 시도한다. 임시 프로필로 여러 번 띄우면 실패(보안 이벤트 4625)가 쌓여 계정 잠금 정책(예: 10분 내 10회 실패 시 계정 잠금)에 걸릴 수 있다.
- `figlib.py shot`은 고정 프로필(`%TEMP%\docfig-chrome-profile`)을 재사용하고, 기존 Chrome의 `Local State`에서 암호 마지막 변경 시각 캐시를 넣어 이 확인을 건너뛰게 한다.
- **`shot`을 여러 개 동시에 돌리지 않는다**(같은 고정 프로필을 동시에 쓰면 일부 스크린샷이 실패한다). 서브에이전트에 나눠 맡길 때도 스크린샷은 한 번에 하나씩 찍는다.
- Chrome/Edge가 없는 환경이어서 `shot`을 실행하지 못했다면 억지로 우회하지 않고, `check` 결과와 함께 시각 스크린샷 미실행 사실을 정직하게 보고한다.

## 7. 자주 틀리는 곳

- 화살표 사이가 좁아 글자가 상자와 겹침 → 상자 사이를 50px 이상으로 넓히거나, 글자를 상자 줄 위쪽 빈 곳(상자 위 8px 안팎)에 둔다. 실제 글꼴은 `text_width` 어림보다 넓게 나오니 여유를 둔다.
- 오른쪽 끝 글자가 `viewBox` 밖으로 잘림 → `anchor='end'`로 왼쪽에 붙이거나 `viewBox` 폭을 넓힌다.
- 그림 위·아래가 비어 있음 → 좌표를 다 옮기지 말고 `Flow(w, h, label, mid, x0=0, y0=90)`처럼 `viewBox` 시작점을 조정해 잘라 낸다. 범례가 위에 있으면 함께 잘리지 않게 확인한다.
- 한 문서에 그림이 둘 이상인데 `mid`가 같음 → 화살촉 marker id가 겹쳐 화살촉이 엉뚱하게 보인다(`check`가 잡음).
- 없는 연결을 실선으로 그림, 또는 계획을 현재 있는 것처럼 그림 → 미구현·단절 구간은 반드시 `gap`(빨간 점선)으로 구분한다.
- 표를 지우고 그림만 남김 → 검색·복사·스크린리더를 위해 표는 남기고 그림을 함께 둔다.
