# 요구사항 인터뷰

모호한 아이디어를 실행 가능한 요구사항으로 정리한다. 개발뿐 아니라 조사, 콘텐츠, 업무 자동화 등에도 적용하며 사용자의 언어로 대화한다.

## 진행

- 사용자가 제공한 목표와 기존 대화를 먼저 읽는다. 저장소에서 확인할 수 있는 사실은 직접 조사하고 다시 묻지 않는다.
- 매 응답에서는 질문을 하나만 하고 답변을 기다린다. 여러 독립적인 질문을 한 문장에 묶지 않는다.
- 다음 결정을 좌우하는 불확실성부터 묻는다. 보통 목적과 대상, 핵심 사용 상황, 최소 범위, 제약, 완료 기준 순으로 확인하되 이미 답한 항목은 건너뛴다.
- 선택이 도움이 되면 현실적인 선택지 2~3개를 제시한다. 추천안을 첫 번째에 두고 이유와 절충점을 짧게 설명한다.
- 현재 환경에서 선택형 질문 도구를 사용할 수 있으면 우선 사용한다. 한 번에 질문 하나와 선택지 2~3개만 넣고 추천안에 `(Recommended)` 또는 도구가 요구하는 표기를 붙인다.
- 질문 도구를 사용할 수 없으면 번호 목록으로 같은 내용을 묻고 직접 입력, 모름, 건너뛰기도 가능하다고 알린다.
- 추천 표시나 무응답을 사용자의 선택으로 간주하지 않는다. 답변에 따라 다음 질문을 바꾼다.
- 사용자가 모른다고 하면 합리적인 제안을 하되 미확정 가정으로 기록한다. 구현 방식은 결과나 제약에 영향을 줄 때만 묻는다.

## 마무리

목표, 최소 범위, 검증 가능한 완료 기준이 명확해지면 인터뷰를 끝내고 다음 중 해당하는 내용을 간결히 정리한다.

- 해결할 문제, 대상 사용자, 기대 결과
- 포함 범위와 제외 범위
- 핵심 사용 흐름
- 제약과 확정된 결정
- 관찰 가능한 완료 기준
- 미확정 질문과 가정, 권장 다음 행동

요약은 대화에 제공하고 사용자가 저장 경로를 지정한 경우에만 파일로 쓴다. 구현까지 이미 요청받았다면 기존 승인 범위에서 이어가며, 인터뷰만 요청받았다면 `실행 계획으로 이어가기`, `요약 수정`, `요약으로 마치기` 중 다음 진행을 한 질문으로 묻는다. 실행 계획을 선택하면 `skills/make-plan/SKILL.md`를 읽고 사용자가 확인한 최신 요약을 입력으로 사용한다.

사용자가 인터뷰 중단을 요청하면 즉시 질문을 멈추고 현재까지의 내용을 정리한다.
