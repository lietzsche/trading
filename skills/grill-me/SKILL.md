# 요구사항 인터뷰

모호한 아이디어를 실행 가능한 요구사항으로 정리한다. 개발뿐 아니라 조사, 콘텐츠, 업무 자동화 등에도 적용한다. 사용자의 언어로 대화한다.

## 시작하기

사용자가 제공한 목표와 기존 대화를 먼저 읽는다. 저장소와 관련 자료에서 확인할 수 있는 사실은 직접 조사하고 다시 묻지 않는다. 주제가 없다면 무엇을 구체화하려는지 한 질문으로 시작한다.

## 인터뷰 진행

- 매 응답에서는 질문을 하나만 하고 답변을 기다린다. 질문 안에 여러 독립적인 질문을 묶지 않는다.
- 다음 결정을 좌우하는 불확실성부터 묻는다. 보통 목적과 대상, 핵심 사용 상황, 최소 범위, 제약, 완료 기준 순으로 검토하되 이미 답한 항목은 건너뛴다.
- 선택이 도움이 되면 현실적인 선택지 2~3개를 제시한다. 추천안을 첫 번째에 두고 추천 이유와 주요 절충점을 짧게 설명한다. 사용자가 자유롭게 답할 수도 있게 한다.
- 선택형 질문의 제시 방식은 아래의 환경별 질문 도구 지침을 따른다. 추천안이 표시되었다고 사용자가 선택한 것으로 간주하지 않는다.
- 답변에 따라 다음 질문을 바꾼다. 모순이나 중요한 누락은 구체적인 사례로 확인하고, 사용자가 이미 정한 방향을 임의로 바꾸지 않는다.
- 사용자가 모른다고 하면 합리적인 제안을 하되 미확정 가정으로 기록한다. 건너뛴 항목도 결정된 것으로 취급하지 않는다.
- 구현 방식은 결과나 제약에 영향을 주는 경우에만 묻는다. 간단한 작업에 고정된 질문 수나 방대한 체크리스트를 강요하지 않는다.

## 선택형 질문 UI

선택지가 있는 질문은 일반 텍스트로 나열하기 전에 현재 환경에서 사용 가능한 질문 도구를 확인하고 우선 호출한다. 스킬 문서의 Markdown 목록만으로 버튼이 생성되지는 않는다. 실제 표시는 클라이언트에 따라 버튼, 카드, 터미널 선택 목록이 될 수 있다.

### Codex

- 현재 모드에서 허용된 `request_user_input`을 우선 사용한다. `request_user_input_async`만 제공되거나 비동기 인터뷰가 적합하면 이를 사용한다. 실제 도구 목록과 사용 조건을 따르며 존재하지 않는 도구를 호출하지 않는다.
- 한 번의 호출에는 질문 하나와 선택지 2~3개를 넣는다. 동기 도구는 `options`의 `label`·`description`, 비동기 도구는 제공된 스키마의 `options` 형식을 따른다. 추천 선택지를 첫 번째에 두고 `(추천)`으로 표시한다. 도구가 `(Recommended)` 표기를 요구하면 그 표기를 사용한다.
- 비동기 질문을 보낸 뒤에는 사용자 답변이 도착하기 전까지 다음 질문이나 답변에 의존하는 작업으로 넘어가지 않는다. 무응답·시간 초과·기본 선택은 사용자 결정이 아니다. 그런 결과만 돌아오면 미응답으로 유지하고 대화로 답변을 기다린다.
- 현재 모드에서 질문 도구가 제공되지 않거나 호출이 금지되면 그 이유를 짧게 설명하고 번호 목록으로 질문한다. 필요하면 `/plan`에서 다시 시작하는 방법을 안내하되, 모드를 임의로 바꾸거나 계획 모드가 모든 환경에서 UI를 보장한다고 말하지 않는다.

### Claude Code

- `AskUserQuestion`이 사용 가능하면 이를 우선 호출한다. `questions`에는 질문 하나를 넣고, 각 선택지에 `label`과 절충점을 설명하는 `description`을 제공한다. 추천안을 첫 번째에 두고 `(추천)`으로 표시한다.
- 서로 배타적인 결정은 단일 선택으로 제시한다. UI가 자유 입력을 제공하면 별도의 중복 선택지를 만들지 않는다. 도구의 실제 스키마와 사용 조건을 따른다.
- 도구가 제공되지 않거나 사용할 수 없으면 번호 목록으로 질문한다. 도구 이름만 대화에 출력하고 실제 선택형 UI를 제공했다고 보고하지 않는다.

### 텍스트 대체 방식

대체 이유는 처음 전환할 때 한 번만 설명한다. 질문 하나, 번호를 붙인 선택지 2~3개, 추천 이유를 제시하고 직접 입력·모름·건너뛰기도 가능하다고 안내한다. 사용자가 텍스트 방식을 요청하면 그 선호를 따른다. 답변 없이 인터뷰를 자동 진행하지 않는다.

## 마무리와 결과물

목표·최소 범위·검증 가능한 완료 기준이 명확하고, 진행을 좌우하는 큰 제약이 해소되면 인터뷰를 마친다. 사소한 미정 사항까지 모두 해결하려고 질문을 계속하지 말고 요약에 남긴다. 사용자가 중간에 정리를 요청하면 현재까지의 답으로 마무리한다. 다음 내용을 짧은 요구사항 요약으로 제시한다.

- 해결하려는 문제, 대상 사용자, 기대 결과
- 포함 범위와 제외 범위
- 핵심 사용 흐름 또는 대표 사례
- 제약과 사용자가 확정한 결정
- 관찰하거나 검증할 수 있는 완료 기준
- 미확정 질문과 가정, 권장하는 다음 행동

해당하지 않는 항목은 생략한다. 요약은 대화에 제공하고, 파일 저장 요청이 있으면 사용자가 지정한 경로에 쓴다. 구현까지 이미 요청받았다면 기존 승인 범위 내에서 이어가며, 새 승인 절차를 임의로 추가하지 않는다. 사용자가 인터뷰 중단을 요청하면 질문을 멈춘다.

## 실행 계획으로 이어가기

인터뷰만 요청받았다면 요약 뒤에 다음 체인을 제안한다. 구현까지 이미 요청받았거나 사용자가 인터뷰 중단을 요청했다면 제안하지 않는다.

1. 요약을 제시한 뒤 선택형 질문 하나로 다음 진행을 묻는다. 선택지는 `실행 계획으로 이어가기 (추천)`, `요약 수정`, `요약으로 마치기`로 구성한다.
2. `요약 수정`을 고르면 지적된 부분을 고친 요약을 다시 제시하고 1단계로 돌아간다.
3. `실행 계획으로 이어가기`를 고르면 저장소 루트 기준 `skills/make-plan/SKILL.md`를 읽고 그 지침에 따라 계획을 작성한다. 사용자가 확인한 최신 요약을 입력으로 넘기며, 확정 결정과 미확정 가정의 구분을 유지한다. 이후 종료 조건은 make-plan을 따른다.
4. `요약으로 마치기`를 고르거나, 답변이 없거나, 무응답·시간 초과·기본 선택만 돌아오면 요약으로 끝낸다. 추천안이 표시되었다는 이유로 계획 단계로 넘어가지 않는다.

질문 도구를 쓸 수 없으면 텍스트 대체 방식으로 같은 선택지를 제시한다.
