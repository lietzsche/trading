# 스킬 메이커 (Skill Maker)

사용자의 아이디어나 반복 업무, 도메인 규칙, 또는 다른 도구의 워크플로를 Codex와 Claude Code 양쪽에서 재사용할 수 있는 스킬로 설계·작성·수정한다. 사용자의 언어로 대화한다.

## 입력과 범위 확인

- 요청에서 **스킬 이름**(소문자·하이픈, 예: `code-audit`, `weekly-report`), **해결하려는 문제와 호출 상황**, **기대 결과물**(대화 응답, 특정 양식의 파일, 다단계 체인 등)을 파악한다.
- 저장소 파일(`AGENTS.md`, `README.md`, 기존 `skills/*/SKILL.md`, `docs/*`)이나 관련 자료에서 확인할 수 있는 사실은 먼저 직접 조사하고 사용자에게 다시 묻지 않는다.
- 스킬의 핵심 범위·산출물 형식·종료 조건이 크게 갈리는 불확실성이 있을 때만 한 번에 한 질문씩 확인한다. 선택형 질문은 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따른다.
- 사소한 공백은 합리적으로 정해 작성한 뒤 결과 보고에 가정으로 남긴다. 아이디어가 아직 초기 단계라 전반적으로 모호하면 `skills/grill-me/SKILL.md`로 요구사항 인터뷰부터 진행할지 안내한다.

## 파일 구조와 진입점

스킬을 새로 만들거나 수정할 때는 기본적으로 다음 세 파일을 함께 구성한다.

1. **공통 원본 (`skills/<name>/SKILL.md`)**
   - 실제 워크플로, 실행 단계, 단계 간 전달할 입력·산출물, 검증 방법, 종료 조건을 모두 이 파일에 작성한다.
   - 워크플로에 견본 양식, 참고 문서, 보조 스크립트가 꼭 필요한 경우에만 `skills/<name>/` 아래에 `assets/`, `references/`, `scripts/`를 추가한다.
2. **Codex 진입점 (`.agents/skills/<name>/SKILL.md`)**
   - 유효한 `name`, `description` YAML frontmatter(들여쓰기 2칸)를 둔다.
   - 본문에는 동작 지침을 복제하지 않고, 저장소 루트 기준 `skills/<name>/SKILL.md`를 읽고 따르도록 안내하는 얇은 진입점만 작성한다.
3. **Claude Code 진입점 (`.claude/skills/<name>/SKILL.md`)**
   - Codex 진입점과 동일하게 frontmatter와 `skills/<name>/SKILL.md` 참조만 둔다.

## 공통 원본(`SKILL.md`) 설계 원칙

- **YAML Frontmatter**:
  - `name`: 스킬 폴더 이름과 일치하는 소문자·하이픈 문자열
  - `description`: 스킬이 무엇을 하는지와 언제 호출해야 하는지(`사용자가 <name> 또는 ...을 요청할 때 사용한다`)를 한두 문장으로 명확히 적는다.
- **본문 구성**:
  1. **입력 / 시작하기**: 호출 인자, 기존 대화 맥락, 질문 전에 직접 조사해야 할 사실, 출력 경로(파일 생성 스킬인 경우 기본 경로 규칙)를 정의한다.
  2. **실행 단계**: 작업 순서대로 각 단계의 목표, 입력과 산출물, 판단 기준을 간결하고 실행 가능한 문장으로 기술한다. 견본 파일(`assets/`)이나 다른 스킬을 참조하면 정확한 상대/저장소 경로를 적는다.
  3. **검증과 마무리**: 산출물이 기준을 충족하는지 확인하는 방법, 사용자에게 제시할 최종 응답 형식, 언제 스킬이 종료되는지(예: 계획·요약 제시로 끝나는지, 파일 작성·커밋까지 수행하는지)를 명시한다. 기존 승인 범위를 넘어서는 작업을 임의로 자동 실행하지 않는다.
  4. **참고(선택)**: 외부 표준, 공식 문서, 또는 모티프가 된 원본 기능이 있을 때만 출처와 지원 범위를 짧게 덧붙인다.

## 환경별 기능 분기와 타 도구 워크플로 이식 (해당 시)

스킬이 특정 클라이언트의 고유 도구를 쓰거나 다른 도구의 내장 명령을 옮겨오는 경우에는 다음 규칙을 추가로 적용한다. 일반 단일 에이전트 워크플로라면 필요한 항목만 선택해 적용한다.

- **선택형 질문 UI 연결**: 사용자에게 선택지를 제시해 결정을 받아야 하는 단계가 있으면 지침을 중복 작성하지 않고 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따르도록 연결한다.
- **스킬 체인 연결**: 여러 스킬을 이어서 실행할 때는 다른 도구의 `/명령`을 그대로 호출한다고 가정하지 않는다. 다음 단계의 `skills/<target>/SKILL.md`를 읽고 어떤 입력을 넘기며 어떤 조건에서 종료하는지 명시한다.
- **서브에이전트·병렬 작업 매핑**: 멀티에이전트 협업이나 격리 실행이 필요한 스킬은 호스트별 실행 방법과 대체 동작(Fallback)을 함께 적는다.
  - **Claude Code**: 서브에이전트 위임 도구(예: `Task` / `Agent` 도구)가 있으면 역할별 목표와 완료 기준을 담아 위임하고, 독립적인 조사·검증은 병렬 호출한다.
  - **Codex**: 현재 세션에서 서브에이전트·멀티에이전트 도구가 제공되면 우선 사용하고, 없거나 제한된 환경에서는 격리된 작업 트리(`git worktree`)나 하위 실행 또는 단계별 역할 전환으로 수행한다.
  - **단일 에이전트 대체 동작**: 서브에이전트를 생성할 수 없는 환경·권한 모드에서도 스킬이 정상 완주하도록, 한 에이전트가 단계별 산출물과 독립 검증을 순서대로 수행하는 대체 경로를 반드시 포함한다.
- **타 도구 기능 이식**: 외부 도구의 전용 명령을 이식할 때는 비공개 내부 프롬프트가 있다고 가정하지 않고, 문제를 해결하는 핵심 절차(예: `계획 수립 → 다중 가설·역할 분할 → 실행 → 독립 검증`)로 분해해 작성한다. 호스트 환경 차이로 인한 제한 사항은 문서에 솔직하게 밝힌다.

## 문서 반영과 검증

1. **문서 업데이트**:
   - `README.md`의 스킬 표에 새 스킬을 추가하고, 본문에 Codex(`$<name>` 및 `/skills`)와 Claude Code(`/<name>`) 사용 예시를 함께 작성한다.
   - 일반 대화 요청도 스킬로 라우팅할 필요가 있으면 `AGENTS.md`의 `Agent-Specific Instructions`에 추가한다(`CLAUDE.md`의 `@AGENTS.md` 참조가 유지되는지 확인한다).
2. **완료 전 검증**:
   - `skills/<name>/SKILL.md`, `.agents/skills/<name>/SKILL.md`, `.claude/skills/<name>/SKILL.md`의 frontmatter(`name`, `description`), 원본 경로, 참조 파일 경로를 확인한다.
   - 현실적인 요청 예시를 대입해 질문 순서, 미정 답변 처리, 단계별 산출물, 종료 조건이 자연스럽게 이어지는지 점검한다.
   - `git diff --check`로 공백 및 줄바꿈 오류를 확인한다.
3. **정직한 보고와 커밋**:
   - 실제 Codex나 Claude Code 클라이언트에서 스킬 목록 표시·자동완성·런타임 호출을 직접 실행해 확인하지 못했다면 그 사실을 명시하고, 파일 생성만으로 클라이언트 발견까지 검증했다고 보고하지 않는다.
   - 검증이 끝나면 `AGENTS.md`의 커밋·푸시 규칙에 따라 작업 파일만 스테이징하여 한글 커밋 메시지로 커밋하고 원격 저장소에 푸시한다.
