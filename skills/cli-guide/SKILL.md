# CLI 명령어 HTML 설명서

지정한 분야의 CLI 명령어를 조사해 `assets/example.html`과 같은 양식의 단일 HTML 파일로 정리한다. 사용자의 언어로 작성하고 대화한다.

## 입력 확인

- 요청에서 **대상**(예: Claude Code, Windows PowerShell, Linux coreutils, git)과 **범위**를 읽는다.
- 대상이 넓어 결과가 크게 갈리면 범위만 한 질문으로 확인한다. 예: Windows → `cmd`, PowerShell, 둘 다. 선택형 질문은 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따른다.
- 사소한 공백은 묻지 않고 합리적으로 정한 뒤 결과 보고에 가정으로 남긴다.
- 출력 경로를 지정하지 않으면 저장소의 `docs/<대상-slug>-cli-guide.html`에 쓴다. slug는 소문자·하이픈으로 만든다.

## 조사

1. 공식 문서를 1차 출처로 한다. 명령 레퍼런스, 사이트맵, 도구 자체 도움말(`--help`, `man`, `Get-Help`)을 우선 확인한다.
2. 블로그·포럼·검색 요약은 보조로만 쓰고, 공식 문서에서 확인하지 못한 항목은 "미확인" 태그를 붙인다.
3. 페이지가 차단(403 등)되면 사이트맵이나 다른 공식 페이지에서 같은 정보를 찾는다. 끝내 확인하지 못하면 그 사실을 보고한다.
4. 명령마다 이름, 분류, 별칭, 한 줄 설명, 상세 설명, 사용 예, 공식 문서 링크를 모은다. 출처에 없는 옵션이나 동작을 지어내지 않는다. 사용 예는 문서에 있는 형식을 따르고, 형식을 확인하지 못했으면 예시 대신 공식 구문만 적는다.

## HTML 구성

`assets/example.html`의 CSS, 레이아웃, 스크립트를 그대로 재사용하고 내용만 바꾼다. 외부 라이브러리나 웹폰트 링크를 추가하지 않는다.

- **header**: `<h1>` 제목(`<대상> 명령어 정리` 등), 한 줄 소개, 조사일과 출처
- **nav.toc**: 섹션 앵커 목차
- **섹션 1 — 시작하기**(선택): 설치·실행 방법, 설정 파일 위치 등 명령을 쓰기 위한 최소 정보를 표나 카드로
- **섹션 2 — 핵심 명령**: 자주 쓰는 명령 6~12개를 카드로. 분류·플랜·플랫폼 제약은 `.tag`로 표시
- **섹션 3 — 전체 명령**: `#cmd-table` 표(명령·분류·별칭·설명)와 `#cmd-filter` 검색창, 클릭 안내 문구 `.hint`
- **footer**: 주요 출처 링크와 조사일

### 펼쳐보기 상세

- 표의 각 행은 첫 칸 `<code>`의 첫 단어가 명령 이름이다. 스크립트의 `DETAILS` 객체에 `'명령': [상세 설명, 사용 예, 문서 링크]`를 넣는다. 사용 예와 링크는 빈 문자열로 둘 수 있으며, 링크가 없으면 `REF`(전체 레퍼런스 URL)를 쓴다.
- 상세 설명에는 용도, 쓰는 상황, 별칭, 관련 옵션·단축키를 2~3문장으로 쓴다.
- 문자열 안의 HTML 특수문자는 `&lt;`, `&gt;`, `&amp;`로 이스케이프하고, 작은따옴표는 `\'`로 이스케이프한다.
- 명령이 많아 섹션이 지나치게 길면 분류별로 표를 나누되, 각 표에 같은 펼쳐보기·검색 동작을 적용한다.

## 검증과 마무리

- `DETAILS`의 키가 표의 명령 이름과 모두 일치하는지 확인한다. 상세가 없는 행이 있으면 보고한다.
- 파일을 다시 읽어 제목, 목차 앵커, 한글 깨짐 여부를 확인한다. 브라우저로 직접 확인하지 못했다면 그 사실을 보고한다.
- 저장소 안에 썼다면 프로젝트의 커밋·푸시 규칙(`AGENTS.md`)을 따른다.
- 결과 보고에는 파일 경로, 섹션 구성, 명령 수, 미확인 항목, 가정을 짧게 적는다.
