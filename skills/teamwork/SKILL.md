# 멀티에이전트 팀 협업 (Teamwork)

한 번에 처리하기엔 범위가 넓거나 여러 모듈·관점이 얽힌 작업(대규모 리팩터링, 저장소 마이그레이션, 복합 기능 개발, 다각도 리서치)을 역할 분담과 통합 검증으로 해결한다. 사용자의 언어로 대화한다.

## 입력과 시작하기

- 호출에 전달된 프로젝트 목표, 대상 범위, 기존 대화를 먼저 읽는다.
- 저장소 구조, 패키지·모듈 경계, 빌드·테스트 명령, 프로젝트 규칙(`AGENTS.md`, `CLAUDE.md` 등)에서 확인할 수 있는 사실은 직접 조사하고 사용자에게 다시 묻지 않는다.
- 범위나 핵심 아키텍처 방향이 크게 갈리는 불확실성이 있을 때만 한 번에 한 질문씩 확인한다. 선택형 질문은 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따른다.
- 사소한 공백은 합리적인 가정으로 기록하고 팀 편성 단계로 넘어간다. 요구사항 자체가 아직 초기 아이디어 수준이면 `skills/grill-me/SKILL.md` 또는 `skills/make-plan/SKILL.md`를 먼저 진행할지 안내한다.

## 실행 단계: 4단계 팀 협업 워크플로

대규모 작업을 무작정 순서 없이 수정하지 않고, 다음 4단계를 순서대로 수행한다.

### 1단계 — 팀 편성 및 작업 분할 (Coordinator)

- 전체 과제를 서로 충돌하지 않는 **독립 작업 단위(Workstreams)**로 분해한다.
- 과제 성격에 맞춰 **2~4개의 전문 역할(Role)**을 편성한다.
  - 구현·마이그레이션 예: `코디네이터/아키텍트`, `코어·백엔드 담당`, `UI·클라이언트 담당`, `QA·통합 검증 담당`
  - 조사·문서화 예: `영역별 리서처 A/B/C`, `팩트체크·통합 편집자`
- 두 작업자가 같은 파일을 동시에 덮어쓰지 않도록 역할마다 **담당 파일·디렉터리 범위(Ownership Scope)**와 **완료 기준**을 명확히 지정한다.

### 2단계 — 공통 인터페이스 및 계약 합의 (Contract Alignment)

- 각 역할이 세부 작업에 들어가기 전에 모듈 간 경계에서 지켜야 할 **공통 계약(Contract)**을 먼저 확정한다.
  - 공유 타입·인터페이스, 함수/API 시그니처, 데이터 포맷, 파일 경로, 명명 규칙
- 선행되어야 하는 기반 작업(순차 실행)과 동시에 진행할 수 있는 독립 작업(병렬 실행)의 순서를 정한다.

### 3단계 — 역할별 분할 실행 (Role-based Execution)

- 각 역할이 배정된 범위와 합의된 인터페이스 계약에 따라 구현·마이그레이션·조사를 수행한다.
- 각 역할은 자신의 담당 범위를 벗어난 파일을 임의로 수정하지 않는다.
- 실행 도중 공통 인터페이스나 스키마 변경이 불가피해지면, 코디네이터 단계에서 계약을 먼저 갱신하고 연관된 역할의 작업에 함께 반영한다.

### 4단계 — 통합 및 교차 검증 (Integration & Cross-Review)

- 모든 역할의 작업 결과를 통합하고 모듈 간 연결부(import 경로, 타입 일치, 상태 전달, 문서 일관성)를 점검한다.
- **교차 검증(Cross-Review)**: 구현 담당이 아닌 QA·검증자 관점에서 요구사항 누락, 엣지 케이스, 회귀 여부를 점검하고 실제 테스트·린트·빌드 명령을 실행한다.
- 통합 오류나 테스트 실패가 발견되면 해당 담당 역할로 피드백해 수정한 뒤 재검증한다.

## 환경별 멀티에이전트·도구 활용

호스트 환경이 지원하는 도구에 맞춰 병렬성과 컨텍스트 격리를 활용한다.

- **Claude Code**:
  - 서브에이전트 도구(예: `Task` / `Agent` 도구)를 사용할 수 있으면, 메인 에이전트가 **코디네이터(Coordinator)** 역할을 맡고 3단계의 독립 작업 단위와 4단계 교차 검증을 서브에이전트에 위임한다.
  - 파일 수정 범위가 겹치지 않는 독립 작업들은 한 턴에 **병렬 서브에이전트 호출**로 동시에 실행한다.
  - 각 서브에이전트에는 `담당 역할`, `수정 허용 경로`, `2단계에서 합의한 인터페이스 계약`, `기대 산출물`을 명확히 전달한다.
- **Codex**:
  - 현재 세션에서 서브에이전트·멀티에이전트 도구가 제공되면 역할별 조사·구현·검증을 분할 위임한다.
  - 여러 모듈을 격리된 작업 트리에서 병렬로 실험·수정해야 하고 환경이 허용하면 `git worktree` 등을 활용한 뒤 메인 작업 트리로 통합한다.
- **단일 에이전트 대체 동작 (Fallback)**:
  - 서브에이전트를 생성할 수 없는 모드나 환경에서는 메인 에이전트가 1~2단계에서 작성한 **작업 분할표와 공통 인터페이스 계약**을 기준으로 각 역할을 순서대로 전환(`Role 1` → `Role 2` → `Integrator/QA`)하며 수행한다.
  - 단일 에이전트 환경에서도 **사전 인터페이스 고정**과 **마지막 교차 검증 단계**를 생략하지 않아 대규모 변경에서의 누락과 충돌을 막는다.

## 결과물과 마무리

통합과 검증이 완료되면 다음 내용을 간결하게 정리해 대화에 보고한다.

- **팀 편성 및 역할 분담**: 정의한 역할과 각 역할이 맡은 작업 범위·핵심 계약
- **역할별 산출물 및 변경 파일**: 생성·수정·삭제된 파일 경로와 주요 반영 내역
- **통합 및 교차 검증 결과**: 실행한 빌드·테스트·검증 명령과 실제 결과
- **가정 및 남은 과제**: 환경 제약으로 생략된 검증이나 후속 권장 작업

기존 승인 범위를 넘어서는 작업을 임의로 실행하지 않는다. 저장소 작업 단위가 완료되었고 프로젝트의 커밋·푸시 규칙(`AGENTS.md`)이 적용되는 경우 해당 규칙을 따른다.
