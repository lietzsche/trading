# 실행 계획 작성

요구사항을 바로 실행할 수 있는 계획으로 바꾼다. 개발뿐 아니라 조사, 콘텐츠, 업무 자동화 등에도 적용한다. 사용자의 언어로 대화한다.

## 입력

- grill-me에서 이어진 경우: 사용자가 확인한 요구사항 요약을 입력으로 사용한다. 확정 결정과 미확정 가정을 구분한 상태를 유지하고 다시 인터뷰하지 않는다.
- 단독 호출인 경우: 호출에 전달된 요구사항, 자유 텍스트, 기존 대화를 입력으로 사용한다. 저장소와 관련 자료에서 확인할 수 있는 사실은 직접 조사한다.
- 목표나 완료 기준이 없어 계획의 방향이 갈리면 부족한 점만 한 번에 하나씩 짧게 확인한다. 선택형 질문은 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따른다. 요구사항이 전반적으로 모호하면 grill-me로 먼저 정리하자고 안내한다.
- 사소한 공백은 묻지 않고 가정으로 계획에 기록한다.

## 계획 작성

다음 항목으로 계획을 작성한다. 해당하지 않는 항목은 생략한다.

- **목표와 완료 기준**: 요구사항에서 가져온 기대 결과와 검증 가능한 완료 기준
- **단계**: 실행 순서대로 번호를 붙인다. 각 단계는 무엇을 하는지, 그 단계의 산출물, 완료를 확인하는 방법을 담는다. 앞 단계 결과에 의존하는 단계는 그 의존을 밝힌다.
- **검증**: 전체 결과를 확인하는 방법과 사용자가 직접 확인해야 하는 항목
- **위험과 대응**: 실패하거나 다시 해야 할 가능성이 큰 지점과 대응 방법
- **가정과 미확정 사항**: 확정되지 않은 채 계획에 반영한 가정과 실행 전 확인할 질문

### 저장소 작업일 때 추가할 항목

작업 대상이 코드나 문서 저장소이면 계획 전에 관련 파일과 프로젝트 지침(`AGENTS.md`, `CLAUDE.md` 등)을 조사하고 다음을 추가한다.

- 단계별로 생성·수정·삭제할 파일 경로
- 실행할 검증 명령과 그 전제 조건. 저장소에 없는 명령을 지어내지 않는다.
- 커밋 단위와 프로젝트의 커밋·푸시 규칙 적용 여부

일정이나 작업 시간 추정은 사용자가 요청할 때만 넣는다. 단계 수를 맞추려고 작업을 쪼개거나 부풀리지 않는다.

## 결과물과 종료

- 계획은 대화에 제시한다. 사용자가 저장 경로를 지정하면 그 경로에 쓴다. 경로를 지정하지 않으면 파일을 만들지 않는다.
- 계획 제시로 이 스킬을 마친다. 계획 작성 요청은 구현 승인으로 간주하지 않는다. 구현이 이미 별도로 요청되어 있었다면 기존 승인 범위 안에서 이어간다.
- 사용자가 계획 수정을 요청하면 해당 부분을 고쳐 다시 제시한다.
