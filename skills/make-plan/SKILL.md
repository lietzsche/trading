# 실행 계획 작성

요구사항을 바로 실행할 수 있는 계획으로 바꾼다. 개발뿐 아니라 조사, 콘텐츠, 업무 자동화에도 적용하며 사용자의 언어로 작성한다.

## 입력 확인

- grill-me에서 이어진 경우 사용자가 확인한 요구사항 요약을 사용하고 확정 결정과 미확정 가정을 구분한다. 같은 내용을 다시 인터뷰하지 않는다.
- 단독 호출이면 요청, 기존 대화, 저장소에서 확인한 사실을 입력으로 사용한다.
- 목표나 완료 기준이 없어 방향이 갈릴 때만 부족한 점을 한 번에 하나씩 묻는다. 선택형 질문은 `skills/grill-me/SKILL.md`의 방식을 따른다.
- 사소한 공백은 묻지 않고 가정으로 기록한다. 전반적으로 모호하면 grill-me로 먼저 정리하자고 안내한다.

## 계획 형식

해당하는 항목만 포함한다.

- **목표와 완료 기준**: 기대 결과와 검증 가능한 완료 기준
- **단계**: 실행 순서, 각 단계의 작업·산출물·확인 방법, 단계 간 의존성
- **검증**: 전체 결과 확인 방법과 사용자가 직접 확인할 항목
- **위험과 대응**: 실패나 재작업 가능성이 큰 지점과 대응
- **가정과 미확정 사항**: 계획에 반영한 가정과 실행 전 확인할 질문

저장소 작업이면 먼저 관련 파일과 `AGENTS.md`, `CLAUDE.md` 같은 프로젝트 지침을 조사하고 다음을 추가한다.

- 단계별 생성·수정·삭제 파일 경로
- 실제 저장소에 존재하는 검증 명령과 전제 조건
- 커밋 단위와 프로젝트의 커밋·푸시 규칙 적용 여부

일정이나 작업 시간은 사용자가 요청할 때만 넣는다. 단계 수를 맞추려고 작업을 부풀리지 않는다.

## 종료

계획은 대화에 제시하고 사용자가 저장 경로를 지정한 경우에만 파일로 쓴다. 계획 요청 자체를 구현 승인으로 간주하지 않는다. 구현이 별도로 요청되어 있었다면 기존 승인 범위에서 이어간다. 사용자가 수정을 요청하면 해당 부분을 반영해 계획을 다시 제시한다.
